# v0.49.9

This patch release stops tool-output cleanup from clearing work that still belongs to the current task, removes a per-turn stall in large sessions, lets free OpenCode Zen models summarize history, and fixes several host and release details. There is no database migration.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart OpenCode 1, OpenCode 2, Pi or Oh My Pi after updating.
- **Rust-mode installs need to update `ck-mc` to the version shipped with this release.** The Rust module, not just the host plugin, contains age-based reclaim and the raw-replay fix; the latter prevents a rare large cached-prefix rewrite when a saved replay ends.

## Fixed

- **Tool outputs now count as old by conversation distance:** after three newer user turns, or once newer content fills 25% of the context window. Before, every cache rebuild counted, so two idle gaps of five minutes or a model switch could clear outputs the current task still needed (#700).
- **Large OpenCode and Pi sessions no longer stall on every turn while checking dropped tool outputs.** The check now reads only what the provider receives, not the tool's display data. On Pi's own native API it still reads the full metadata, because that API sends it (#704).
- **Pi no longer rewrites the cached prefix twice in a row after recovering from a saved request.** Cleanup that used to need a second rewrite now lands in the first.
- **OpenCode Zen free models can summarize history on OpenCode 1 and OpenCode 2.** Zen's free tier only accepts requests from OpenCode itself, so on Pi and Oh My Pi those models stay unavailable, and the failure now says so plainly.
- **`/ctx-status` on OpenCode 2 shows the session model's own threshold.** This change was contributed by @manorit2001 in PR #706 (#705).
- **`ck module status` reports the actual `ck-mc` release version (#710).**
- **A smart note whose schedule would run less than once a day is recompiled once with a daily check,** instead of failing every night.
- **Primer candidates sort the same way on every machine,** whatever the system language.
