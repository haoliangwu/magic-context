# v0.49.13

This patch release fixes queued removals after failed turns, bounds memory verification, and restores automatic history re-embedding after an embedding model change. It also reduces unnecessary retrospective calls and fixes memory mapping when a model's answer arrives after its tool calls. There is no database migration.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart OpenCode 1, OpenCode 2, Pi or Oh My Pi after updating.
- **Active sessions automatically re-embed their history after an embedding model change.** Old-model embeddings are replaced only for active sessions.

## Changed

- **Memory verification may stop early and save partial results.** It checks five memories at a time, with token limits per batch and run, and a four-minute deadline.
- **The retrospective runs less often.** It calls the model only when a new user message follows an assistant reply, rather than repeatedly reviewing unchanged conversations.

## Fixed

- **Queued removals survive recovery from a failed turn.** The next permitted cache rebuild applies saved drops instead of resending the recovery copy. Thanks to @Qiiks for the report in the issue 713 thread.
- **Pi keeps previously removed thinking out of rebuilt requests.** Recovering a failed turn no longer brings that thinking back during later cache rebuilds.
- **Memory mapping keeps the model's final answer after tool use.** A blank capture no longer rejects a valid answer: the shared check now ignores whitespace-only output before validating it, and Pi keeps the runner's final text after tool-only streams. Thanks to @ICEY16360 for the report in issue 718 and for the shared fix in PR 719.
- **Memory verification reports why it could not finish.** OpenCode 2 verification also gains the code-navigation tools available on other hosts, with guidance to inspect structure before reading full files.
