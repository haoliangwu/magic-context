# v0.49.10

This patch release fixes Oh My Pi sessions on the OpenAI Codex lane that refused every turn after the model's first tool call. There is no database migration.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart Oh My Pi after updating. OpenCode and Rust-mode installs are unaffected by this release.

## Fixed

- **Oh My Pi on the Codex lane no longer refuses every turn after a tool call.** Oh My Pi stores each Codex reply exactly as the provider returned it, including its reasoning and tool calls, and sends that stored copy back on later turns. Magic Context's check before sending only recognised stored replies that held just a message, so once the model had called a tool, every later turn was refused at the same point with `comparison=content`. The check now skips stored reasoning and matches tool calls by ID. Every text Magic Context prepared must still match the stored copy exactly, so history it didn't prepare is still refused. Thanks to @Zireael for a detailed report (#714).
- **A refusal caused by an unexpected error inside that check now says where it happened,** instead of reporting a misleading `row=0 … comparison=count`.
