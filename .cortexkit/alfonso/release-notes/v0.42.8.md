# v0.42.8 tokenizer calibration — notes draft

**Not ready to publish:** runtime integrations have landed on the task branch, but the complete Phase A inventory and verification matrix are not finished. See `PARITY.md` and `docs/reports/tokenizer-calibration-phase-a-verification.md`.

## Changes implemented

- History materialization converts a provider-token history allowance to a local prose allowance in OpenCode, Pi and Rust. Curve pressure and exact demotion use the same units. Conversion occurs when rendering, not in cache-invalidation identity.
- Protected tool-window membership uses class-calibrated mass, retaining whole tag groups and the newest-three structural minimum. Original source boundaries weight prose and tool input/output without changing stored raw counts.
- Raw fallback and last-known-good replay require complete calibrated estimates and a known current-model window. A byte-size approximation can reject early but cannot prove fit. Recovery cannot disarm on incomplete or nonfinite telemetry.
- Historian request admission counts the assembled source and system prompt under the selected producer's seed, reserves output once, and retains the 3% margin. Source chunk allowances use the producer model, not the main model.
- Emergency planning separates current served mass from retained replacement mass. Skeleton tokens are not credited as removed; cached content is previewed without mutation. The existing once-per-pressure-episode latch remains.
- Static calibration is frozen per session at authorized bust boundaries and replayed on defers/restarts. Table revisions take effect only at the next priced bust. Runtime L/P capture, candidate EMA and learned provenance were removed; calibration comes only from curated seeds and family fallback.

## Intentional behavior changes

**Fit guards can refuse requests they previously admitted.** The previous 1.02× oversized atomic-source fixture is one explicit example: clipping source text to a raw allowance does not prove the complete calibrated prompt fits. That case now sends no producer prompt, publishes no new range, and records `producer_prompt_exceeds_window` rather than advancing coverage. In particular, unknown models use `max(2.0, largest static measured ratio)` for fit, rather than trusting raw local counts. A family-inherited seed is treated as a seed, not as unknown. Missing measurements cannot be made complete by multiplying known components. Pi's storage-failure fallback currently lacks complete observations and therefore refuses rather than sending on a byte-only estimate, even for a small valid LKG replay. Durable snapshots are still captured and hydrated; missing system/tool observations do not authorize sending them. An explicitly observed, fitting calibrated replay remains admissible at the shared fit helper. Rust refuses a fallback producer whose own context window has not been supplied; it does not borrow the primary producer's window.

`protected_tokens` remains a real/provider-token floor, and `history_budget_percentage` remains a fraction of the established real window. Existing configuration values are not rewritten or rescaled. In the integrated history/protection paths, calibration makes those values mean their documented units rather than raw tokenizer units. This can shorten history or protect fewer tool tags for models whose local tokenizer undercounts.

No new configuration knob, migration, schema fence change, sidecar, or persisted learning record is introduced. Tokenizer goldens and durable raw token counts are unchanged. The tool-schema ratio used for tool I/O is a policy seed, not a measurement proving every tool output has that drift. Provider framing and later host rewrites remain unmeasured.
