Two failures in 0.42.6 stop every turn on OpenCode 2 before the model is called, and one of them hits any data directory that has ever run OpenCode 1. Rolling back is not a workaround: measured on a 2.0.11 host, released 0.42.5 does not answer at all, on a fresh data directory or an aged one. If you run OpenCode 2, upgrade.

## Fixes

- **OpenCode 2 refused every prompt on a data directory that had ever held OpenCode 1 sessions (#493, deltacat).** OpenCode 2 migrates an OpenCode 1 `opencode.db` in place and keeps the v1 tables beside its own, so the file carries `message` and `part` as well as `session_message` and `session_v2`. The store-generation guard added in 0.42.6 reads any store carrying `message` and `part` as OpenCode 1 and refuses generation-specific access to it; on the v2 lane that refusal becomes an interrupt before the provider. The prompt is accepted, no transform runs, no provider request is made, the host records the turn as `idle outcome=interrupted`, and the TUI paints nothing after your own message. It is not a first-prompt cost and it is not slow: on the reproduction the first turn was refused in 453 ms and the next three in 18, 13 and 13 ms, every turn of every session, forever. A store carrying `session_message` **and** `session_v2` is now accepted as v2 whatever v1 tables it kept, because `session_v2` is written only by an OpenCode 2 host; detection is otherwise unchanged, so a live 1.18.x store is still v1 and a downgrade is still safe. Verified end to end on the reporter's shape — an aged root driven by OpenCode 1.18.30 with 0.42.5, then reopened with `@opencode/cli` 2.0.11 in the real TUI. If you cannot upgrade at once, `export OPENCODE_DB=opencode2.db` gives OpenCode 2 its own store file and the leftover tables are not there to confuse the check.

- **That refusal is no longer silent (#493).** Any failure in the pre-provider context read — an unreadable host store, a non-durable context database, a permission problem — interrupts the turn, and the reason only ever reached `console.warn`, which is OpenCode's own server log. `magic-context.log`, the one artifact support asks for, said nothing at all, which is why this issue cost two rounds of triage on a reporter who did collect diagnostics. The refusal now names its cause and its session in the plugin log. This does not change whether a turn is refused, only whether anyone can find out why.

- **A session past its context threshold refused every following turn on OpenCode 2.** The pre-provider admission check in 0.42.6 refuses at 95% of the model's catalogue window with no upper bound, and everything that could bring usage back down — the transform, compartment scheduling, the historian — runs downstream of that refusal, so nothing ever un-sticks the session: a reading at twice the window refuses exactly as one just over the threshold does. The predicate now lives in `v2/hooks/provider-admission.ts` with both missing properties restored and the reason stated beside them. Usage already past the provider's window is admitted, because the provider's own overflow error is the only place the real limit is ever reported and the handling that shrinks history lives further down the same pass. Pressure is measured against the raw provider window, not the window minus the reply reserve: on a 100,000-token model the reserved window is 91,808, so 90,000 tokens is 90% of the window but 98% of what is left, and the tighter denominator refused turns that used to reach the historian. A host compaction newer than the measured reply still admits one request. Both properties are now pinned by tests that name them one by one.

- **`keep_subagents: true` again retains every settled Magic Context child (#500, Cyantix).** A 0.42.0 regression made the privacy class bypass the operator's explicit retention setting, so Dreamer tasks, smart-note evaluation and compilation, and user-memory review disappeared even while historian and memory-migration children remained. The setting now covers every settled child. Unsettled privacy children are still archived and reaped by the age-gated sweep; kept Dreamer transcripts can carry memory-pool text and user messages from the same operator's other sessions, and they accumulate until manually cleared.

- **The dreamer has not run on Pi or OMP since 0.42.5 (#496, Qiiks).** The OpenCode orphan sweep asserted its precondition with a throw, the sweep runs inside the global message-history maintenance stage, and that stage runs before the per-project loop inside the tick's single `try`. On Pi and OMP, whose sessions do not live in the OpenCode store, every tick since 2026-09-15 ended at that assertion before a single task was dispatched — the reporter's store showed 605 of 637 task rows past due with 364 carrying no status at all, which is the shape a scheduler leaves when it never reaches the rows. The sweep now parks on a harness it cannot read and re-probes a day later instead of throwing, reporting cooldown in between and never opening the OpenCode store. Message-history maintenance and each project's maintenance are contained separately, so one stage's failure costs only that stage. And the first stage to fail in a tick is persisted and shown as **MC-D09** — a `Dreamer blocked` row naming the stage and its age in `/ctx-status`, a warning block on hosts with no overlay, and one line per harness in `doctor` — cleared by the next tick that completes every stage. MC-D09 is deliberately distinct from MC-D08 (tasks this host cannot run) and MC-S05 (a task failing on its schedule): those say some maintenance is not happening, MC-D09 says none of it is.

- **Pi 0.86.0: tool declarations survive a fold again (#485, aoguai and XWIlluDelu; #490, Micheal107480, the same mechanism).** Pi 0.86 moved the system prompt and the tool set into transcript `system` entries. Magic Context injected its own head in front of them and treated them as ordinary prose, so after the first compaction the request went out with an empty tool array and the model narrated calls or stopped just before making one. System-role entries are now structurally exempt from every Pi-lane mutation — trim, tagging, `ctx_reduce`, LKG, emergency reclaim, the hygiene count and native replay — and keep their canonical raw ordinals while contributing no foldable prose. The m0/m1 head lands after the leading system run so Pi's own `getInitialSystemMessage` still finds `messages[0]`, and an initial system entry displaced by an extension is promoted to served index 0 with ordinals unchanged. The deferred marker drain adopts Pi's `appendCompaction` snapshot only when the tools and prompt it resolves equal the ones that were folded; otherwise the marker is refused for that pass, the Magic Context fold is served, the pending marker is retained and the divergence is logged. Pi exposes no retraction, so a divergent entry that was already persisted is re-checked against the then-current journal before any later adoption. The product's mirror of Pi's resolvers is pinned against the installed 0.86 resolvers by a differential test. OMP 18.2.6 and Pi 0.85 are unchanged.

- **A reasoning-only assistant could vanish on a free pass.** `ToolMutationBatch.finalize` swept every message left without a meaningful part whenever any tool removal replayed, so a reasoning-only assistant survived the priced marker-seam pass (it was pruned on the separate pre-prepare copy) and then disappeared on the next defer pass — a prefix rewrite on a pass that was meant to change no bytes, caught on a live session rather than in a fixture. Pruning is now scoped to the tool owners a pass actually touched and adopted only on a priced pass, through a reserved `@tool-sweep-scoped` ledger entry, so sessions that have not adopted it keep serving byte-identical defers.

- **A defer pass that has not adopted the scoped sweep serves what the session was last served.** Such a pass computes both candidate arrays and asks which one reproduces the rows the session was last served, read from the durable LKG snapshot: the legacy array (`matched_old`, also when both match, because indistinguishable candidates are no reason to change what a session is paying for), the scoped one (`matched_scoped`, which adopts on that pass), neither (`matched_neither`, serve the status quo and let the next priced pass adopt), or no snapshot at all (`lkg_absent`, adopt now). One policy per pass, logged under `tool_sweep_lkg_mismatch` with the condition and both divergences. A Pi clone now carries the adoption marker, priced marker-seam passes prune the array that is actually served so no empty shell reaches the next defer, and a session that was mid-drain when it upgraded from a build without the atomic drain rule loses exactly the rows below that build's committed boundary, once — the bound is stated at the refusal site and pinned by a cross-version upgrade test.

- **The compaction-marker drain and the in-pass prefix trim are one decision.** The host's source order is frozen before tag replay and pruning, so the trim can still locate a boundary row that was removed from the live array, and the drain refuses to commit on any pass where the trim is not proven applied. Before this, the drain could advance while the served window still carried rows below the new boundary, which is a bust on the next pass.

- **Channel-1 nudges no longer starve.** An invalidated tail-hygiene baseline is re-measured on the defer pass that finds it — naming the reason once (shorter, tag status, protection entered, and the rest) — instead of holding "baseline unevaluable" until the next cache bust happens to arrive, and the newest message is never frozen. Same shape on OpenCode, Pi and the Rust module, which persists the re-measured baseline once on the invalidating pass. No band, threshold or knob changed.

- **Rust module: a subagent froze its last-known-good replay and never released it.** Served-output fingerprints named a frame id, so a subagent's harness-notice prompt read as a mutation of `m0` and pinned the session's baseline; they now name a frameless synthetic message (`mc_synthetic:N`), and a session with no served prefix adopts its new baseline instead of pinning it. A hermetic 20-pass subagent stability scenario covers the cycle.

- **Rust module: a subagent's late-minted tags were withheld forever.** Tags first discovered after their block was served are withheld from non-busting passes and released on the next independent bust — but the release gate asked "is this session paying for a cache bust", which a subagent never is, so the withhold branch ran on every pass and the release branch on none. The gate now asks its own question, which is identical for every other session and false for a subagent, since a subagent recomposes its served array each pass and holds no cached prefix to protect. These two ride the `ck-mc` module binary, not the npm package.

- **Rust mode: recovery no longer folds twice.** The adapter's healthy-route stall probe launched an overlapping silent resend through the bypass lane while the original mutating request was still in flight, so two concurrent transforms each folded and the session paid two HARD passes where one identity change had occurred; instrumentation showed both evaluations reading the same persisted epoch. The probe now waits on the original deadline, yielding a raw timeout, then one HARD, then SOFT. This one is adapter-side: it ships in the npm package and takes an OpenCode restart rather than a module bounce.

- **Shadow embeddings are discarded when their registration is retired mid-embed (#470, Qiiks).** A provider round-trip can take seconds (tens on a cold Synapse load); if the shadow registration was unregistered or replaced in that window, the returned vectors were still written under the retired lane and read as valid backfill on a later re-arm. The live registration generation is re-checked after the await in all three scopes and the write is refused with a named reason; a retired item's outcome no longer feeds the stall detector for its replacement.

- Local Transformers.js model downloads now honor `HF_ENDPOINT` in both native and WASM runtimes, so a Hugging Face-compatible mirror can be used without changing cache or vector identities (#459, sisttri).

## OpenCode 2

The list below is the parity work; the two failures above are the reason to upgrade. Rust transform mode on OpenCode 2 is **not** in this release.

- **Magic Context compaction markers survive the OpenCode 1 → 2 store conversion.** OpenCode 2 drops a v1 compaction pair when its summary has no `time.completed`; older Magic Context markers omitted that field, so converted long sessions could load their entire history, consume extreme memory and CPU, and never reach the plugin. New markers stamp matching created/completed times, and `magic-context doctor` reports affected Magic Context-owned rows without touching native summaries. **Before upgrading OpenCode, stop the host and run `magic-context doctor --fix`** to backfill them. If OpenCode 2 already completed conversion and doctor reports missing converted markers, stop every host, clear only `kv.migration.v1-v2`, then run `opencode serve --port N` by hand until `SELECT value FROM kv WHERE key = 'migration.v1-v2';` reads `{"phase":"completed"}`. Large stores can take minutes; `opencode service start` may kill the server as unresponsive during that work. Do not edit `session_v2` or `session_message` directly.
- **Long-session reads are page-bounded.** The v2 adapter decoded the entire session on every raw read; on long sessions this took minutes and gigabytes before the first turn — fixed.
- **OpenCode 2 boundary and id lookups stay SQL-bounded on long converted sessions.** Trigger, snapshot, index and historian paths no longer decode the full `session_message` history to resolve one id, ordinal, count or short range.
- **Synthetic rows created by OpenCode 1 → 2 conversion no longer strand the historian between compartments.** Rebase absorbs synthetic-only gaps into the earlier compartment, reports narrative gaps without hiding them, and v2 notices let older rebases tolerate the same safe gap.
- **Tail-cached historian validation still reads older converted gaps.** When a synthetic-only gap predates the cached tail, validation now fetches that bounded range from storage instead of treating the uncached row as missing.

- **The terminal sidebar is the real component (#488, from PR 487's diagnosis by blasphemy).** The OpenCode 1 sidebar is mounted on the v2 `sidebar.content` slot through the host's OpenTUI runtime registry, using the precompiled component rather than a second compile target (the 0.4.2 and 0.5.10 runtime helpers are byte-identical). The plain-text projection is kept only for a host that registers no runtime-module ids. A v2 RPC listener backs it, so the numbers it paints are real ones; the paint itself is proven by a PTY capture.

- **`/ctx-status` is one view on every host.** A shared section model owns which rows exist, their labels, their order and their colour tones; OpenCode 1 and 2 draw it with the same compiled dialog and Pi with its own line renderer. The mouse-only diagnostics toggle is gone, every row carries an explicit theme foreground (collapsed rows were invisible on a light theme), and labels sit in fixed columns with a one-column fallback instead of wrapping mid-word.

- **The `/ctx-*` commands exist on OpenCode 2.** All six are registered server-side through the host's command transform, so they are listed by the host's command API and can be run against a session with no TUI at all; the keymap layer is kept for dialog rendering, with `ctx-flush`, `ctx-embed` and `ctx-wrapup` added to it.

- **Dreamer tasks run where their transport allows (#492 findings 2 and 3, null-axiom).** Each task's capability is recorded as a transport — single-shot, host-only, or tool-loop. `evaluate-smart-notes`, `review-user-memories` and `promote-primers` run on OpenCode 2 through the hidden single-shot carrier, with length-capped and empty completions refused before parsing. A tool-loop task is refused per task and named **MC-D08** in `/ctx-dream`, `/ctx-status` and the run records, instead of the whole scheduler looking idle. Manual `/ctx-dream` uses the same capability filter and the canonical scheduler prune.

- **Hidden historian children are deleted when they are retired (#481 and PR 482, qoole).** Under a provider that fails every model — a pool at its weekly quota, say — each failed run retired its child and the next run made a new one: 114 hidden sessions in about two and a half hours. Deletion now goes through the host's own session-delete endpoint, reached via the service registration file that `serve --service` writes, with plain `fetch` and no runtime dependency on the host package; the retired list is pruned and bounded and a spaced boot sweep clears an existing backlog. Deletion binds to the owning host registration (pid-matched at discovery, path persisted, a 404 counted only from the owner), and a child that cannot be bound stays retriable as **MC-H02** rather than being dropped (#492 findings 5 and 6). On top of that, a run that failed only on settled provider errors keeps its child and reuses it, decided by a typed provider error and a finish check rather than a message prefix — every other failure still retires it.

- **Hidden prompts no longer carry an output cap the provider rejects (#483, qoole).** The hidden-child hook set `maxOutputTokens` to 32,768 on every hidden prompt, which the host sends as `max_output_tokens` and the ChatGPT-subscription (Codex) backend rejects, so every historian run under that login failed. The cap and the temperature now go on the wire only when the run carries an authored value from config, for every provider alike; the producer-window arithmetic keeps its own default and is pinned by a test.

- **`transform_mode: "rust"` on OpenCode 2 says so out loud (MC-S06).** It resolves to the TypeScript transform with one warning and a parity row rather than silently half-resolving, and the RPC handlers no longer branch on an unresolved mode.

- **Smaller v2 gaps closed.** Tool definitions are measured from the request draft, with a four-pass byte pin proving no served byte moves, and the lane no longer registers a persistent tool transform on every context pass (#492 finding 4). Cold usage recovery reads the v2 message table with generation guards and finite-token math. There are compaction-off rows in the TUI, an app-slot fallback for `/ctx-*` when the keymap provider is unmounted, typed fail-closed refusals and bounded deletion tombstones. Tool-owner backfill gates on the v1 tables it reads rather than asserting a store generation (the capability-gate shape comes from PR 486, DGVY), and the doctor's boundary-table choice combines the resolved host generation with the store schema (#489). A host reporting the `0.0.0-beta` pre-release shape is treated as OpenCode 2, not 1.x.

- **Session coordinates survive the OpenCode 1 → 2 store conversion, in both directions (#492 finding 1, null-axiom).** When OpenCode 2 opens a 1.x store it splits synthetic content into rows of its own and replaces completed compaction pairs with one native record, so every positional ordinal Magic Context had saved for that session moved by one or more; a compartment covering messages 4–9 could omit its own last message or take in one outside it, a queued `ctx_reduce` drop for one fragment applied to the merged text, and the message index carried the last message twice. Downgrading moves them back. Each session now records the projection its coordinates were derived against (`coordinate_generation`), and the first pass after a flip in either direction re-derives every saved coordinate from surviving message ids — compartments and their facts, the message index and its watermarks, chunk windows, note anchors, the protected-tail floor — in one transaction, then pays one HARD. A compartment whose anchor no longer resolves is marked `unresolved`: left out of range recovery and of `<session-history>`, still readable by id, re-evaluated on the next flip, never guessed. Queued drops that would broaden are discarded and reported. `doctor` lists sessions still pending a rebase and unresolved compartments per session, and the log carries one line per rebased session. Verified by driving a session through a real 1.18.30 host, a real 2.0.5 conversion, and 1.18.30 again with the plugin loaded on every boot. Fresh OpenCode 2 sessions, Pi and project memory were never affected.

## Migration

- **The schema fence moves from 85 to 88.** Migration v88 adds `session_meta.coordinate_generation` and `compartments.rebase_status` for the conversion rebase above. Migration v86 adds a per-session `tags_version` to `session_meta`, maintained by triggers on `tags`, so a foreign write no longer forces a full tag-map reload. Migration v87 decides each session's harness label from the OpenCode store, read-only: newer `session_message`/`session_v2` activity means `opencode2`, newer `message`/`session` activity means `opencode`, and a session absent from both is left alone. It replaces migration v85, which rewrote `opencode2` → `opencode` across the board and so mislabelled a real OpenCode 2 install (#475, qoole); v85 is now inert, still recording its version row, and v87 repairs what it did. An unreadable store changes nothing, logs once, and reports the skipped sessions through `doctor`. Both migrations are idempotent.

- **On first open the migrations run once, and every Magic Context instance sharing the database must be restarted** — OpenCode servers, Pi and OMP processes, instances in other projects — because a running older instance can block the migration. After it applies, a build at fence 85, 86 or 87 refuses the database rather than silently running without context management, so update pinned installations too. Downgrading the plugin does not downgrade the database.

- **A legacy database could fail its upgrade on Linux.** The `tags_version` triggers v86 installs write `session_meta.tags_version`, and an older trigger-bearing migration renames tables under them, so a long-stale database died at v49 on SQLite 3.53. The column is now healed before those migrations run. In the same area, v86's triggers inflated the change counts `bun:sqlite` reports, so the tag-write guards were made trigger-insensitive and the trigger now creates a complete `session_meta` row rather than a sparse one — cloned sessions would otherwise have lost their counters and watermarks.

## Removed

- **`/ctx-session-upgrade` is gone** — the command, the OpenCode 1 dialog and its reminder, the RPC handlers and the runner behind them — and with it the once-per-project 9-category to 5-category memory migration. That migration is the dreamer curate task's job now: `/ctx-recomp` already rebuilds legacy compartments, they render without any upgrade, and curate maps legacy categories as it touches them. Databases are untouched: the migration guard rows, the `session_meta` upgrade columns and the `historian_runs` rows recorded as upgrades stay inert. Legacy-compartment detection is kept for Pi's status line.

## Also fixed

- **Equal-importance memories tie-break on reinforcement recency (#474, Qiiks).** Once the injection budget binds, ordering an entire `importance = 50` band by creation id carries no signal, so selection now falls back to verification and last-seen recency on OpenCode, Pi and the Rust module (memory render epoch 3: one priced HARD per rust session, TypeScript adopts on the next natural HARD). `/ctx-status` and its detail surface carry a per-band importance histogram with an unclassified denominator, which is what the investigation turned on: the reporter's pool "peaking at 50" was the unclassified pile, not a classifier collapsing to the midpoint. Classified memories spread across the whole scale — on our own store, 271 of 7,092 sit at exactly 50 — while unclassified ones sit at 50 or NULL and nowhere else. Checking that found `classify-memories` failing on several of our own projects for a week, which is the fix below.

- **`classify-memories` failed on every run in rust mode.** The engine's `session.send` returns either an active run or a pending submission when the session already has a run, the producer read only the active shape, and one provider session was reused across the whole fallback chain, so any attempt that ended without its run ending left the session occupied for the next model. Every fallback attempt now gets its own session, a queued send is a named transient error with its submission retracted, every attempt's failure is reported instead of only the last model's, and a scheduled dreamer task that keeps failing surfaces in `/ctx-status`.

- **Auto-compaction conflict detection no longer disables the plugin on a config-less `OPENCODE_CONFIG_DIR` (#484, tim-mcdonald).** A launcher that points the variable at its own hooks directory does not move OpenCode's global config: OpenCode reads the global directory and merges `OPENCODE_CONFIG_DIR` last, as an addition at the top of the precedence order. The detector read that one directory instead, found no file, fell through to the `auto: true` default and switched itself off, leaving nothing managing the window. It now reads every layer OpenCode reads, in OpenCode's own order for the host generation, and an absent `compaction` key everywhere is inconclusive rather than plugin-disabling. Underneath that, the resolved-config arm that should have answered from the host directly was rejecting the ordinary `{"compaction": {"auto": false}}` shape because it required a `prune` key OpenCode does not materialise; an absent or non-boolean `prune` now takes OpenCode's documented default.

- **The historian says what actually failed (#491, expiren).** The v1 historian reader surfaces the child assistant's persisted error and finish fields instead of collapsing provider and auth failures into "Historian returned no assistant output".

- **The retrospective builds a prompt that fits (#473, SK-DEV-AI).** The collector clamps oversize user lines, admits the assembled prompt against the child model's usable window through the shared producer-window guard (oldest first, the frontier advanced only past what was scanned), and collects only the configured recency window (30 days by default). After a size-rejected child run it persists a smaller retry budget and then advances past the admitted frontier, so an identical prompt is never rebuilt. The reporter's 2.19 MB / 683k-token shape now admits at 25 KB / 7.8k tokens.

- **Rust mode: workspace-shared memories and embeddings after an update (#478 and #479, iceteaSA).** Under module authority the `ctx_memory` facade classifies each id — a mirrored row of this project goes to the module, a workspace-shared row belonging to another project is served from the host read model — and the two refusals are distinguishable: "not mirrored yet" is transient, "not owned by this project's module" is permanent. Batches report per id, mappings are accepted only from this project's module, and every module-side mutation pulls its touched rows back before the embedding pass, so an update no longer strands its vector until authority drains.

- **Pi and OMP: a configured `contextWindow` no longer overrides window overlays.** It was treated as provider-observed truth on both hosts.

- **Rust mode: store-state refusals say which kind they are.** An empty store handle becomes `store_opening` (retryable, with elapsed time), `store_lease_wait` (retryable, with a window and a redacted descriptor), `store_open_failed` with a reason and descriptor origin (terminal), or `store_unavailable` only when no handshake ever arrived; transform and the `ctx_*` facade wait briefly on the request lane for an in-flight open, and the open failure reason reaches health. The old message named a cause that cannot occur and sent bug reports to the wrong repository.

- **Rust mode: the deferred-notes nudge arms on a real boundary advance.** Its historian-complete trigger now arms from the module's materialized boundary advance, seeded from the persisted marker across restarts and never on a repeated boundary; rust-mode sessions previously saw only the commit and todo arms.

## Carried from 0.42.5 and 0.42.6

These shipped earlier in the 0.42.x line. They are listed because neither release that carried them works on OpenCode 2 — 0.42.6 for the sessions described at the top, and 0.42.5 on that host at all — so for those users they arrive with this one.

- Local embeddings no longer pin a CPU core after the model loads (#453): the injected WASM ONNX runtime is forced to one thread before the pipeline is constructed, and vectors are byte-identical.
- `ctx_note` has one id field (#460): `note_id` and `note_ids` collapsed into `note_ids`, so providers that send every declared property no longer fail a write. Like any tool-surface change, it costs one priced pass per session on the first turn after the upgrade — an upgrade transition, not a recurring charge.
- Pi resolves embedding routing before registration (#462, Qiiks), through the same resolver OpenCode uses.
- Auto-update no longer disables itself after the first update (#466): an updater-authored pin carries its provenance, and any other exact pin is still respected as your opt-out.
- Historian chunks no longer chain across consecutive tool arcs (#467, Mte90): the head escape admits one connected component and stops, and a component that cannot fit alone is split at its largest tool-result boundary.
- Rust-mode memory ids are host ids in every mode (#468, iceteaSA), translated at the tool boundary in both directions.
- Image fingerprinting no longer tokenizes image payloads (#452), dreamer `curate` runs one memory category per scheduled window (#451), and local embeddings initialize under OMP on the WASM runtime (#441).

## Performance

- **Defer passes on large sessions are cheaper.** The post-transform phase no longer re-measures an unchanged tail on every pass (38 → 6 ms on a 2,250-message session), and the rust-mode adapter no longer re-parses the replay document when its source text is byte-unchanged (apply 13 → 2.5 ms). Served bytes are identical.

- **The module store stops writing on passes that change nothing.** Its grow-mostly cache maps move from a rewritten blob to rows, a byte-identical pass writes nothing and holds its row version, and comparison happens in SQL over a packed count/length/row-state fingerprint rather than by re-serializing every identity row. An idle pass drops from 8.3 KB of WAL to none and an active pass from 7.6 MB to 3.2 MB. Module-side: it rides the `ck-mc` binary and its own store migrations.

## Tests

- Host-behavior e2e scenarios are written once and run per host from the mode manifest (OpenCode 1, OpenCode 2, Pi, OMP) through one harness contract; the manifest refuses a host missing from a scenario without a stated reason.
- Several wall-clock test budgets that read the CI runner instead of the code (#472, Qiiks) now assert size ratios or same-process comparisons; absolute caps run only under `MC_PERF_GATE`.
- The four host lanes are green on the folded manifest — OpenCode 1 54/54, Pi 41/41, OMP 36/36, and OpenCode 2 from 12 of 41 to 34/34 — with host-imposed divergences declared rather than patched over. The OpenCode 2 and OMP lanes also run in the Linux container.
- Rust crates had no CI runner at all, which is how a subagent regression sat on master for two days; there is now a nightly job for them.

Feature PRs need the design agreed before the implementation, and they need to cover every harness we support.
