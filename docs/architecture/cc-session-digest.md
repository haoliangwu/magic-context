# Claude Code session ↔ MID digest (`ccd/v1`)

**Scope.** This is an alignment key, not Thalamus's MID-assignment fingerprint or a content-authentication claim. Thalamus assigns `ccm-{N}` to positional request messages; the module stores `(MID, digest_version, digest)` from **INPUT** CK messages before transform/reduction. The session reader computes the same key from Claude Code JSONL. Retain the version with every persisted digest; never compare different versions or reinterpret old rows after a rule change.

## Canonical bytes

For one logical message, serialize the three-element array `["ccd/v1",ROLE,BLOCKS]`. `ROLE` is `"user"` or `"assistant"`; `BLOCKS` is an ordered array of two-string arrays `[KIND,VALUE]`. Serialize **UTF-8 JSON without a BOM, newline, or spaces**: arrays and strings only; `,`/`:` separators (only commas occur in this shape); JSON string quoting with `"` and `\` escaped, controls U+0000–U+001F escaped using JSON short escapes for backspace, tab, LF, form feed and CR, otherwise lowercase `\u00xx`; leave other Unicode code points (including non-ASCII and U+2028/U+2029) as UTF-8, and do not escape `/`. Reject unpaired surrogates/invalid UTF-8; no Unicode normalization. Hash these bytes with SHA-256 and store the **full 64-character lowercase hexadecimal** digest. The array schema and version remove object-key-order ambiguity and separate block boundaries without an ad hoc delimiter. Do not include message ids/MIDs, ordinals, timestamps, cache directives, extras, tool payloads, or file metadata in the bytes; tool-use/result ids in the pairs above **are** included.

| CK INPUT block → file `message.content` block | Canonical pair / handling |
|---|---|
| `CkKind::Text.text` → `type:text.text`; file scalar `content` → one text block | `["text", text]` after removing only trailing U+0020 SPACE, U+0009 TAB, U+000A LF, U+000D CR, U+000B VT, U+000C FF, in any run. Preserve leading/interior whitespace; preserve a resulting empty text block. Never concatenate adjacent text blocks. |
| Whole-block reminder text | Omit a text block only if its **original** text starts at byte 0 with `<system-reminder>` and, after the above trailing trim, ends with `</system-reminder>`. A mention of that tag inside ordinary text, a leading space, or text after the closing tag is not a reminder. Do not inspect or strip nested tool-result output. |
| `ToolCall.id` → `tool_use.id` | `["tool_use", id]`; name, input and `provider_executed` excluded. |
| `ToolResult.id` → `tool_result.tool_use_id` | `["tool_result", id]`; tool name, output and error state excluded. |
| `Reasoning`, `RedactedReasoning` → `thinking`, `redacted_thinking` | Omit completely, including signatures/data. |
| `Media.kind` → `image`, `document`, etc. | `["media", kind]`, with kind exactly one of `image`, `document`, `file`, `audio`, `video` (lowercase). No media bytes, source, filename or MIME type. A native file block uses its `type` if one of these; otherwise apply unknown rule. |
| `Opaque.kind` / unrecognized native `type` | `["unknown", kind]`, where `kind` is the exact case-sensitive native type string; if no string type exists, `kind` is the empty string. An opaque block whose kind is one of the listed native kinds follows that kind's rule; `thinking`/`redacted_thinking` remain excluded. Never hash an opaque payload. |

**Decision:** fixed typed media/unknown placeholders sacrifice payload distinction but permit both sides to agree without fetching attachments or normalizing arbitrary provider-specific data. **Decision:** trim only six ASCII trailing whitespace characters, not language-dependent Unicode whitespace. **Decision:** whole-block reminders are excluded before text normalization; partial embedded tags are user text. These are contract choices, not observed Claude Code guarantees.

## Reader and join

1. Locate the main file by exact basename `<session-id>.jsonl` under `~/.claude/projects/` (recursive enumeration; do **not** derive or decode a project-directory name from a path). For an agent, use the same session's `<session-id>/subagents/agent-<agentId>.jsonl`, not the parent's transcript. Require a unique matching file in the selected scope; absent/ambiguous files produce no join, not a guessed path. Do not mix parent/agent scopes or separate session ids. **Decision:** discovery is by id rather than path reconstruction because Claude Code project directory encoding is not a stable API.
2. Read physical JSONL order. Only `type:user` and `type:assistant` with `message.role` matching the type and `isSidechain != true` are candidates in the main file. `isMeta` user records **are** candidates: Claude Code sends them on the wire (for example the `<local-command-caveat>` record before a slash command's output), verified against ingress captures 13655–13663. For an agent transcript, read its own user/assistant records in order (do not import sidechain rows from the parent). Ignore `summary`, `system` (including `compact_boundary`), `attachment`, `progress`, mode/permission, titles, cost, file-history snapshots/deltas and other non-message records. Ignore the first `type:user` record immediately after each `system` record with `subtype:compact_boundary` (without crossing another record); it is a generated compaction replacement, not an old message. Do not classify other user text by its wording. **Decision:** the boundary-relative summary rule avoids treating an arbitrary user mention of a summary as generated content.
3. A file `message.role:assistant` maps to CK `role:assistant`; file `message.role:user` maps to CK `role:user`, **including user messages containing only `tool_result` blocks**. File scalar content is one text block, array content retains block order. A role `system` is never a candidate on either side. If an eligible role has no blocks after exclusions, its blocks array is `[]` (different from `[ ["text",""] ]`). Unsupported/malformed block values follow the unknown rule; records missing a valid role/content are logged and skipped.
4. **Merge consecutive user records, before any dedupe.** Within a compaction segment, each run of physically consecutive candidate user records becomes one logical user message, whose blocks are each record's blocks appended in file order (a scalar record contributes one text block). The run ends at an assistant record, a `compact_boundary`, or the skipped generated replacement. Claude Code sends such a run as one wire user message with one text block per record (observed: `isMeta` caveat + `/compact` command name + command stdout + the next typed prompt arrive as one message with four text blocks). This step must come before dedupe: removing a replay copy first could make two runs adjacent that never were on the wire, and they would wrongly merge. **Not yet observed:** whether consecutive assistant records with *different* `message.id` also merge on the wire, and whether a `tool_result` record followed by a typed prompt merges by the same run rule (likely). Until a capture shows either, assistant records merge only per `message.id`, and a user run includes `tool_result`-only records like any other user record.
5. Assemble assistant records with the same nonempty `message.id` into one provider message, in first-appearance order; append each record's content blocks in file order. Identical repeated record content for that id contributes blocks only once, including when replayed after compaction. If a repeated id carries distinct blocks, append them, never replace earlier blocks. An assistant row without a nonempty `message.id` remains a separate logical message. Do not use JSONL `uuid` as the provider id. For merged user messages from step 4 (normally no provider id), dedupe replay copies by the ordered `tool_result.tool_use_id` tuple when nonempty, then by canonical role+block bytes when no ids exist. Apply those user keys **across compaction replay segments only**; identical user prompts within one segment remain separate. If user records have a nonempty `message.id`, use that first. Keep the first occurrence as the logical message's position; identical replay copies do not create new messages. On conflicting content for a reused user id/tool-result-id key, keep first and log conflict rather than silently combine different messages. **Decision:** segment-scoped content dedupe preserves intentional repeated prompts while eliminating compaction replays; a `compact_boundary` starts a new segment.
6. Give each surviving logical file message a zero-based **reader ordinal** in first-occurrence order, including those with no MID. Persist that ordinal independently of any `ccm-{N}` ordinal. These file records are the single deduped logical transcript used for old-history reads and `ctx_expand`.
7. On the wire, project each `TransformRequest.messages[*].ck` **as received** with its envelope `mid`; include all non-`system` INPUT messages, even those outside the currently transformable prefix. Ignore the top-level Anthropic `system` projection (Thalamus removes it before sending CK). Do not digest `pass_output.ck_messages`, generated m0/m1 summaries, or post-transform blocks. If Thalamus puts a synthetic message into INPUT, compute/store its digest but mark it ineligible to claim a file record when `ck.meta.synthetic` is true; other generated content with no file counterpart remains unmatched and is logged. In particular, never let wire `role:system` consume a file ordinal. **Decision:** synthetic messages get diagnostics but cannot steal a real matching file row.
8. Join eligible version-matched wire rows and file rows in order, **one-to-one**, by digest. Choose a maximum-length order-preserving matching (LCS); among equal-length solutions choose the lexicographically earliest sequence of `(file reader ordinal, wire input index)` pairs. This makes duplicate digests use the first available file occurrence in order without reusing it. Across compaction, compare against stored pre-cut `(MID,version,digest)` rows in original input order (not just the truncated current wire array); a re-minted MID is a distinct row. A row with no pair is unmatched: file rows retain their reader ordinals and have null MID, while wire rows retain MID but have no file ordinal. Log session/agent scope, version, counts of matched/unmatched per side, and for each unmatched/conflicting row its side, ordinal or MID, reason and digest prefix (never raw text/tool output). Do not close gaps by incrementing MIDs or by assigning a nearest record.

**Observed shapes (redacted):** the live ingress captures 13655–13663 include scalar and block-array content, tool-only user turns, `system` messages in `messages`, and reminders as whole text blocks; the live session file includes assistant records sharing a provider `message.id`, compaction replays and non-message metadata. Thalamus `mid/assign.rs` mints `ccm-{N}` and its own distinct structural/identity fingerprints. The live probe did not demonstrate a subagent compaction; the subagent scope rule above is a **decision**.
