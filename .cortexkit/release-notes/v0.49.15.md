# v0.49.15

This patch release fixes tag prefixes in Pi and Oh My Pi, keeps Oh My Pi's WebSocket follow-ups working, and makes background memory work more reliable. There is no database migration.

Pi and Oh My Pi users also get the Pi fixes from 0.49.14, whose Pi package never became installable: damaged session records no longer block a session, refusals name their real cause, long sessions load tags in the background, and an outdated tag load retries automatically. Thanks to @Zireael for the report in issue 723.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart OpenCode 1, OpenCode 2, Pi or Oh My Pi after updating.

## Fixed

- **History compression accepts a chunk that covers every message.** A complete chunk is no longer rejected just because there is no next message left to preserve. The prompt and validation now agree in both TypeScript and Rust modes. Thanks to @null-axiom for the report in issue 727.
- **Pi hides tag prefixes while the model is streaming.** The leading tag no longer flashes in the displayed answer. Oh My Pi now also removes the prefix from saved assistant text; its streaming display cannot yet be changed through the extension API. Thanks to @CodingOX for the report in issue 730.
- **Reloading the OpenCode 2 plugin stops its old background work.** Hidden runs are cancelled when their plugin instance is replaced, and shared database readers close when the last instance releases them. Thanks to @Bearmancer for the report in issue 735.
- **Background Pi requests use a sensible output limit.** Background requests now send the configured output limit, or 32,000 tokens by default, instead of allowing an oversized request that OpenRouter could reject for insufficient credit. Memory verification stops starting new batches at its deadline but gives a batch already running up to two more minutes to finish.
- **Oh My Pi's WebSocket follow-ups keep working.** Follow-up requests and todo reminders no longer fail with "missing current receipt signature" when they continue the session's last managed response and their new items match the prepared request exactly. WebSocket transport is on by default, and turning it off with `providers.openaiWebsockets: "off"` is no longer needed as a workaround. With Hide Secrets on, a follow-up whose new items contain a hidden secret still refuses. Thanks to @Zireael and @IdealBoy709 for the reports and source-level diagnosis in issue 686.
- **Pi's tests no longer interfere with the primer test.** A cached mock from another test no longer changes the primer's result. Thanks to @iceteaSA for diagnosing the test isolation problem in issue 736.
