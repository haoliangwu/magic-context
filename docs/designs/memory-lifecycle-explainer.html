A current claim set, not another event log

Remember what matters.

Today, project memory accumulates facts. R2 starts smaller: keep evidence and candidates durable, make every writer accountable, and give the operator one usable approval inbox. Attention changes and bulk history repair come later.

R2 · proposed, not implemented Local, self-contained explainer

Source of truth: Project memory lifecycle. “Today” means the implementation described by that design, not a new audit of your live store. The trials used copied stores and did not change memories.

01 / The one-minute version

Less prompt baggage. More accountable knowledge.

  • Keep episodes in compartments; keep reusable claims in memory. A compartment is a saved, dated episode summary. Its fullest narrative is P1; P2–P4 are progressively shorter versions. It remains the source of evidence, not a second memory row.
  • First release: foundations, not the whole lifecycle. Verification reaches the memory row; anchored candidates survive in a pending queue; all writers share one revision/evidence applier; extraction omits the memory block and reconciliation records shadow new / covered / abstain decisions; a fleet inbox makes review usable.
  • Project activity, not calendar aging. Count distinct compartment publications since accepted reinforcement. A project idle for three weeks loses nothing. Importance × activity freshness stays in shadow until replay beats importance-only selection.
  • Revise without erasing. Keep previous prose, metadata and evidence in history. Superseded rows leave ordinary search, but deliberate history lookup and audited restore remain available.
  • Keep background work off the cache clock. Preserve the applied revision snapshot, text, delta and image. Requested current search can appear in the tail; it does not rewrite the frozen automatic head. Bulk backfill is deferred unless its full barrier is proven.
  • One inbox across projects, not interruptions. Scheduled topic-grouped digests lead to full before/after claims and dated evidence. Approval binds exact revisions. Keep, reject and snooze remember decisions; an Ask-style phone alert is one digest pointer, not one per proposal.
  • No autonomous semantic transitions. Rewrites, merges, replacements, retirements, restore conflicts and standing-rule promotion need revision-bound approval. Keep the pending queue, journal and cache projection; defer usage freshness, rescoring, weighted mural and broad event repair behind their own measurements.

03 / The new model · proposed

A memory is a claim with a reason to remain useful.

Each live claim gains a revision and distinct evidence records. One immutable journal owns history; proof totals derive from claim-specific observations. Keep last-observed, last-verified and last-used separate. Citations identify the project, conversation, harness, compartment and original message lineage. An import timestamp is not a proved occurrence date.

Constant freshness

Standing rule

An explicit user instruction or saved operating rule, with original evidence and revision-bound promotion approval. An agent save only proposes standing status.

Example: the user-stated process-termination prohibition in the rescore trial. Inferred imperative wording does not qualify.

Exit: an explicit, evidenced revocation or replacement. Silence or a code change cannot revoke it.

Longer activity half-life · shadow

Structural fact

Architecture, configuration semantics, an external limit, a naming decision or a mechanism with continuing consequence.

Example: the shared Transcript abstraction described in the rescore trial—a mechanism reused across message representations.

Refresh: a new observation or genuine confirmation restores freshness.

Shorter activity half-life · shadow

Situational fact

Current, changeable state that matters for continuing work: a temporary environment constraint, open operational state or provisional configuration.

Example: the temporary fleet hold in the rescore trial. Preserve its uncertainty; a plan is not an accomplished result.

Exit: decay reduces attention; evidence, not age, decides a correction or retirement.

Episode is not a live memory

Episode

Something done, investigated, released or measured without an independently reusable claim.

Example: the codebase dead-code cleanup in the rescore trial, when it records only work completed rather than a lasting constraint.

Keep: the compartment narrative. Archive legacy episode-memories only after reviewed backfill.

This is provisional vocabulary, not a validated truth/decay model. Episode is an admission disposition, standing rule an authority policy, and structural/situational are volatility assumptions. Split mixed claims only with approval. Design §3 · Rescore examples

Importance × freshness

Importance reflects consequence of not knowing and breadth of applicability. It is stable between reviews; repetition does not increase it. Shadow freshness uses project activity since evidence supporting the whole claim—not calendar days or agent recitation.

weight = importance × freshness

Standing rules: shadow freshness = 1. Other live classes: freshness = 2−publication age / class half-life. Count genuinely new compartment publications across the canonical project, not tool-heavy message chatter or session-local counters. Recomp, retries, restore and repair do not add activity. Capture one ordinal/policy; unknown legacy evidence stays unknown. The first release does not activate this weight or change the mural policy.

Three separate signals—not one self-reinforcing heartbeat

  1. Last-observed. Shadow “covered by #N” maps the new fact to specific target claims. A narrow repeat cannot refresh unrelated clauses of a compound memory. Keep the candidate until its coverage is actually reviewed.
  2. Last-verified. Save backing files, checked commit and actual confirmation on the current revision. Mapping, skipping, a refusal or an unchanged fallback is not confirmation.
  3. Last-used. Scoped citation/consumption telemetry is separate from truth evidence. Usage-driven freshness is deferred; an agent quoting injected memory is not independent corroboration.

Distinct grounded observations count as proofs; usage alone does not prove truth. Retries, prompt copies, duplicate citations, classify and cue compression add no reinforcement. Old backfilled evidence keeps its old observation time; repair time is not new evidence. Search counts are telemetry, not permanent promotion. Design §3

Later measured attention policy; knowledge is not discarded.

  • Prompt text: protected standing rules first, then highest-weight whole claims within the text budget.
  • Mural cue: remaining cue-worthy claims with current cues, within the image budget, on a vision-capable model.
  • Search-only: low weight, stale/missing cue, image overflow or unselected claims on a non-vision model. Full current text remains searchable.
  • Archived, via explicit history: reviewed episodes and superseded/retired claims. Not a decay tier, not an ordinary search hit—even by ID.

Tier floors and cue capacity are open. Keep the configured text budget in initial shadow replay; no trial establishes a new budget. If protected rules cannot fit, report a capacity problem rather than silently substituting vague cues. Design §3

04 / The new write path · proposed

Give extraction and reconciliation separate jobs.

What the gate catches

Missing identifiers, paths, units, refusal codes and named keys; invented target clauses; non-verbatim evidence; missing inventories or unevidenced replacements. An actual wrong raw rewrite was rejected for fabricated ellipsis text.

What it cannot establish

Whether a real quotation contradicts a claim. Whether surviving tokens retain their operative meaning. Whether “new” is already covered. It missed a weakened detach guarantee and a workaround mistaken for removal of an API limitation.

Rejected rewrite → old row untouched, original fact pending. The proposed design does not repeat the trial’s automatic all-new fallback. Approval remains required until independent preservation/contradiction review passes held-out tests.

05 / Non-destructive changes · proposed

Current truth on the row. Previous truth in history.

Using the same source-backed transition, the row keeps its ID and gives actionable current limits. “Was X, now Y” belongs in current prose only when the transition itself helps future work.

Before · #23697

Attachment-cache limit: 256 MiB.

Attachment scope and eviction behavior are still valid and must survive the update.

After · same ID

Attachment-cache limit: 384 MiB total / 288 MiB per entry.

Retain the same scope and eviction behavior. The earlier bound is history, not a competing search result.

{
  previous_text: "prior complete prose, including the 256 MiB bound",
  changed_at: apply time,
  reason: state_update,
  evidence: source compartment and qualified message range,
  source_ids: [23697]
}

This illustrates the journal shape; source prose, evidence coordinates and dates are intentionally not fabricated. The full revision journal also records old class/category/importance/status, hashes, actor, rubric/model, observation key and successor relationships.

  • Update: the old revision leaves ordinary search; the current row remains. History preserves the full earlier prose and metadata.
  • Merge or replacement: archived source/predecessor rows leave semantic, full-text and explicit-ID memory search, and future cue selection. Successor links lead to current knowledge.
  • Restore: a new audited revision on the original ID. Active successors or same-hash rows require a reviewed conflict decision with all-source revision checks. Keep intervening history; do not restore old sharing permissions or use eager unarchive epochs.

Already-served text and images remain frozen until an independently authorized correction/fold. Ordinary restore waits for a natural fold; bulk repair and its undo have the stronger barrier described below. Design §4

06 / Verification, the inbox & later repair

Finish the accounting. Make review usable.

Verify: finish the accounting

Write confirmation, complete file mappings, checked commit, evidence and reinforcement together on the correct revision. Audit legacy mismatches on a copied store; uncertain matches need a new check. Do not reset reinforcement to repair time.

Every writer: the same boundary

Historian, verify, curate, tools, dashboard and later backfill submit the same revision/evidence envelope. No alternate SQL writer bypasses approval. Unchanged checks may automate; semantic changes may not.

Classify and attention: measured later

Blind memory-specific calibration precedes periodic rescoring. Activity freshness must beat importance-only replay. Weighted mural policy needs its own usefulness test; no forced histogram.

Events: keep existing evidence

Repair only references needed by accepted evidence. Broad re-anchoring is deferred until its added value is measured. A trajectory change from a test or self-review is not a user instruction.

Both stale-retirement and reconcile-check trials are complete.

Reconcile-check’s reviewed action precision was 60% (6/10 known), with four wrong accepted actions in each pass. Labelled stale detection changed from 6/21 to 4/21. A real quote from an erroneous SQLite comment supported a false retirement. Quotes establish provenance, not contradiction; an unchanged fallback is not positive verification.

Curate trial · Completed reconcile-check

One fleet inbox, across projects

Topic-grouped, risk-aware cards show complete before/after text, removed and kept claims, exact revisions, dated evidence and its authority, source/caller links, dependencies and pending prompt adoption. Approvals bind that exact decision; stale cards return to review. Grouping is not blanket approval of a model batch.

  • Keep / reject / snooze: preserve current knowledge, remember rejection until genuinely new evidence, or postpone to a later digest. Cosmetic rewrites and retry IDs are not new evidence. Pending facts do not silently disappear.
  • Scheduled digests: review when convenient, not per-turn prompts. An Ask-style phone notification points to the digest, never to each proposal.
  • Backlog telemetry: count, oldest age, arrivals versus decisions, review minutes and per-stage token/spend. Paid retries slow down when review cannot keep up; episodic publication and candidate capture continue.

Later one-time repair—deferred, not a first-release job

  1. Inventory and preview. Freeze eligible IDs, source revisions, registered histories and missing evidence. Show workload, calls/tokens/embeddings and a provider-based cost envelope; disclose unknown billing. Confirm project, budget and model profiles before paid work.
  2. Trace evidence. Prefer original publication/range links, then compatible retrieval. Check P1 and expand raw source when needed. Top-k matches prove earliest located evidence and lower-bound observations—not first occurrence or complete proof counts.
  3. Classify. Blind-score with the new rubric and origin evidence. Flag episodes and possible rules lacking explicit origins.
  4. Resolve transitions. Order evidence by occurrence time, preserve valid claims and use the same approval-gated, revision-checked history applier. Newer does not automatically mean truer.
  5. Archive episodes. Only after evidence is recoverable and classification approved. Keep the compartment record and old memory audit.
  6. Optionally rescore compartments. An independent confirmed overlay subjob, not a prerequisite for memory repair. Leave base summaries, ranges and messages untouched; emit no new facts.
  7. Review final survivors and adopt. Revalidate evidence/class/importance against the post-transition revision. Current requested search can appear in the tail; automatic head adoption waits for independent HARD. Bulk repair cannot ship without the complete projection barrier.

P1-only rescoring is the recommended arm, not an exact-score oracle: an unchanged rerun crossed bands for 10/60 compartments, with mean absolute change 4.33. Extra P2/recent titles showed no quality advantage. The wording trial’s intervention change 4.34 was below repeat noise 4.62. These compartment trials do not validate memory importance or half-lives. Rescore trial · Wording trial

Later jobs: preview → confirm → progress → inbox review → pending head adoption.

Pause/resume/cancel and audited undo belong to the same durable project job. Completion is per item; resume keeps the frozen input set. Reattach an admitted model run after disconnect rather than paying again while its outcome is unknown. Changed inputs become stale for a new preview.

The fleet inbox is the approval surface, not /ctx-memory-repair or per-turn prompts. Doctor stays read-only; later dreamer reuses confirmed jobs. Nothing runs as paid inference during startup or migration.

07 / Cache safety · proposed contract

Background work changes knowledge, not the rebuild schedule.

m[0] is the frozen prompt baseline: memory text, compartment history and the paired mural image. m[1] is its saved additions/corrections. A HARD fold rebuilds that baseline. A SOFT refresh updates only the delta on a rendering opportunity already authorized for another reason. A defer replays both unchanged.

Which changes may appear when?
ChangeIndependent SOFTNatural HARD
Live new claim or textual correctionMay ride the already-authorized delta; never creates the opportunityFold into the new baseline
Age, proof, class or importanceNo reranking of existing attention or delta admissionsRecompute from the captured snapshot
Mural / compressed cuesNo image regeneration or swapUse current eligible cues with the same selected weights
Bulk repair, score overlays and undoWithhold bulk content, archives, additions and tier changesAdvance the conversation’s applied revision markers

SOFT must pin membership and revisions, not just an ID watermark. Persist each admitted delta claim’s revision and creation-time priority; new admissions cannot displace old ones. Apply the projection before eligibility, successor chains, forced IDs or budgets. For applied A1 → deferred repair A2 → live A3 based on A2, withhold A3 until HARD. Withheld operations stay pending. Pending lifecycle count or size cannot manufacture pressure/HARD permission; oversized groups wait instead.

One text / cue / correction manifest. If a memory was only a frozen image cue, its eligible live correction must still override that cue on independent SOFT, without changing image bytes. Current full-text search stays available when only an older revision or a cue is visible.

Score repair needs render-only overlays. A bare compartment importance update can request an early HARD in Rust and invalidate full-row boundary identities. Leave base rows untouched; join effective scores only after a natural HARD is selected.

Permission is counterfactual. Would this pass change the served prefix or lose its cache without pending lifecycle work? Pin both the Rust marker probe and marker-only commit to applied revisions, scores, clocks and image. Dashboard approvals must not call eager epoch setters. Background cue compression does not change Rust’s persisted mural hash: it reads the frozen applied image, not the live cues.

Ownership is decided. Canonical evidence/revisions live in context.db. TS/Pi applied tuples live beside their frozen caches there; Rust’s tuple lives with its cache in store.db. Handoff and paired backup must preserve complete tuples, never mix old images with new text.

Privacy is not decay. Existing ownership, visibility and explicit privacy revocations keep their stronger invalidation paths. “Background work never busts the cache” must not suppress those safety actions.

This is a required implementation contract, not an invariant proved by the model trials. Shipping tests must compare actual served text/image/boundary bytes through defer, SOFT, HARD, restart and undo, with deliberate negative controls. Design §7 · Rescore cache contract

Trials still open before activation
  • Extraction omissions: the paired control is complete, but durable-fact recall and full-memory variance are not. Use its full-memory-only families as regression controls, not assume stripping preserves every useful fact.
  • Safety and operator capacity: cache/authority parity across OpenCode 1/2, Pi and both Rust transports; reviewed semantic preservation beyond reconcile-check’s errors; measured fleet inbox minutes, arrivals and backlog age.
  • Later experiments: lexical-slot/per-fact ablations, blind memory scoring, activity freshness versus importance-only, weighted mural, evidence tracing and bounded bulk-job cost. No model trial proves served-byte safety.

Release order: earn each step

  1. Agree the applied snapshot, evidence, approval and storage contracts; name tests and negative controls before implementation.
  2. Capture durable anchored candidates and repair unchanged verification accounting; no mass live stamping.
  3. Run extraction without the memory block and shadow new/covered/abstain continuation. Keep pending candidates on failure or uncertainty.
  4. Route every writer through the shared applier; pass revision, cache and runtime parity tests before inbox approvals apply.
  5. Pilot one fleet inbox and scheduled digests; bound paid work by real review capacity, not silent fact eviction.
  6. Stop there for the first release. Automated transitions, usage freshness, periodic rescoring, weighted mural, event re-anchoring and bulk backfill need separate measured gates.

Bounded implementation slices

Each design slice fits one small mason PR; split by runtime/authority instead of assigning a fleet refactor. A spec-exit gate approves the state machine, independent expected values and named red/green controls before implementation. Product tests and activation gates remain separate.

Storage, correctness and admission contracts
  • Verification contract repair: row status, complete files, checked commit and reinforcement across writers.
  • Schema/journal/pending publication: spec exit settles ownership, original lineage, transaction/crash behavior and fresh/incremental schemas; no deferred bulk job payload.
  • Applier and writer routing: spec exit approves the all-source revision/approval matrix, restore/hash/successor cases and exact-repeat rules. Denial tests cover every writer.
  • Shadow reconcile: spec exit accepts anchored new/covered/abstain goldens, claim-specific coverage/recitation and full-memory-only controls.
Conversation continuation, one runtime at a time
  • TypeScript OpenCode: same-child second turn, bounded retries, partial failures and memory-owner handoff.
  • Rust host: stage-aware claim/report protocol, retained child conversation and late-report defenses.
  • Rust Broca: distinct per-turn send identities, stage usage and unknown-outcome recovery.
  • Pi: same-conversation carrier, cancellation/context limits and routing; no fresh-session call advertised as cached continuation.
Cache projection and current search—not new attention weights
  • Applied snapshot: spec exit fixes tuple placement, atomicity, handoff and backup; expected text/image/manifest bytes are independently specified.
  • Materializers: one worker per TS/Pi/Rust. Spec exit maps every branch to pinned marker probe/commit, SOFT membership, A1/A2/A3 and cue-only correction tests.
  • Search: spec exit approves current-versus-frozen revision/representation cases for semantic, FTS and ID lookup, including history-only tombstones.
Fleet inbox backend, UI and throughput pilot
  • Backend: spec exit fixes exact decision tokens, rejection/snooze/new-evidence policy, digest identity and publication-preserving backpressure. No eager dashboard setters.
  • UI: spec exit approves full-text/claim/evidence cards, stale/conflict handling and accessible digest flows. One decision per exact proposal, even in a grouped view.
  • Pilot: measure 25-project arrivals, review minutes, throughput, age and spend before enabling fleet-wide proposals. Preserve existing opt-outs.

Migration dependency: rebase on the final preceding performance/Pi-marker release, then allocate actual context/store versions and fingerprints. The expected v95→v96 order is not verified allocation. Context holds canonical records; Rust also needs its cache migration. No paid backfill or weakening of old-writer guards.

10 / What the review changed

Stronger contracts. Less unearned automation.

Only two of five requested Athena seats ran: gpt-6-astra and gemini-3.8-flash. This is not measured panel consensus. R2 takes Astra’s blockers as the stronger reading and checks factual claims against source.

  • Cut the first release: verify accounting, durable candidates, shared applier, shadow reconcile and a fleet inbox. Keep history and cache projection; defer broad lifecycle activation.
  • Correct the evidence ledger: paired full memory emitted 86 facts versus stripped 139/133, with about 18% known stripped re-emission. Eighteen rule families in thirteen cases appeared only in full memory—including no-copy policy and reasoning budget—so stripping is not just a token optimization or proved recall improvement.
  • Reject quote-based authority: reconcile-check reached 60% reviewed action precision, not safe autonomous repair. Partial coverage cannot refresh whole compound claims; injected recitations are not independent evidence.
  • Resolve the cache details: pin probe and commit, persist admitted revisions, withhold dependent A3, share text/cue/correction manifests, and allow requested current search in the tail.
  • Reject one source-refuted allegation: Rust’s persisted mural hash comes from the frozen applied mural, not background cue compression. The separate speculative-composition risk still needs protection.
  • Decide the clock and review product: publication-count freshness in shadow; one cross-project inbox with scheduled digests, exact approvals and remembered rejections. No calendar rot, slash-command approval workflow or notification storm.
