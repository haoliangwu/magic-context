# Config page design proposal

Open [`mockup.html`](./mockup.html) directly in a browser. Designed at **1728 × 1085**; no build, external assets, requests, or persistence. Inputs can be edited, but Save Changes, other dashboard pages, project configuration, and connection testing are intentionally unavailable. Reload resets the preview. No dashboard source was changed.

## What changed and why

- **One full-width section at a time**, with a persistent section index: General; Context window; History; Memory & search; Background models; Dreamer schedule; Prompt surface; Advanced. Balanced field rows inside sections replace unequal neighboring cards. Compaction Management and Smart Drops move into Context window; System Prompt Injection moves into Prompt surface instead of being buried beside SQLite tuning.
- **Defaults before exceptions.** Context defaults stay visible. A collapsed disclosure contains one compact table for all **19 distinct models** (19 Cache TTL entries and 9 Execute Threshold % entries), with columns for the four existing per-model settings. Blank cells inherit the corresponding fallback/default; unset execute-token thresholds use percentages, and unset output reserve is derived, not a hard-coded 16,384. No repetitive “Custom…” selects or bright red removal buttons.
- **Quiet metadata.** Config keys are hidden until “Show config keys” is checked. No Live badges. Restart/reload badges are limited to explicitly documented compaction and Pi todowrite/overlay lifecycle requirements. Missing numbers use real placeholders; missing booleans are identified as inherited defaults rather than pretending the file explicitly sets them. Longer original descriptions remain in small expandable explanations.
- **Honest copy.** Cache TTL is the provider prompt-cache lifetime MC assumes, not a queue timer, and does not change the provider's cache. Clear Reasoning Age removes older reasoning blocks whole, only during an already-cache-rebuilding pass (the 0.45.0 behavior). History Budget % keeps the editor's label and fractional units; it is not presented as the number 15.
- **Explicit harness boundaries.** Historian and Dreamer share a model-only OpenCode/Pi/OMP tab group. Primary, default, and fallback qualifiers have their existing distinct labels; fallback removal stays inside its card. History controls and Dreamer registration/docs controls are outside these tabs. Mural's Cue Compressor Model is explicitly shared, not falsely given a per-harness config path.
- **Twelve tasks in a compact table.** Schedules are plain words in 24-hour time. Click one to reveal its full cron expression and five-field legend, task variant/thinking level, and the two existing promotion thresholds. Separate task harness tabs change only model overrides; schedule edits and promotion thresholds are synchronized across tabs. On/off maps to a nonempty/empty schedule, **not** an invented task enable key. Turning a task back on restores its last preview schedule (or the editor preset for an initially disabled task).
- **Same visual language.** Palette, system/local font stacks, 4/6/8px radii, 12/16/24px spacing, blue pills, 176px sidebar with the same six labels/icons, and 28px status bar are taken from the dashboard stylesheet. No downloaded fonts are needed.

## Snapshot and field coverage

Values were read from Ufuk's user JSONC without modifying it. The embedding credential was replaced with literal bullets **before inclusion**; it is absent from HTML, JS, and comments. OpenCode uses `google/antigravity-gemini-3.8-flash` with the `openrouter/deepseek/deepseek-v4.1-flash` fallback; the historian has primary `high` and fallback `medium` variants. Pi uses the actual stored `google-antigravity/…` and `ollama-cloud/…` IDs. OMP has no explicit model block, so shows the built-in fallback-chain placeholder rather than copying OpenCode's values. All 19 TTL entries, 9 percentage entries, 12 schedules, and the two explicit task-model overrides are represented.

All structured controls from `ConfigEditor.tsx` and its model/task components have a home. Local Model dtype appears only when Local is selected; Pi Todo Overlay appears only when Pi Todowrite Tool is enabled, matching the existing conditional controls. The default score placeholder is **0.6**, from the schema, rather than the editor's stale 0.55; historian timeout defaults to the schema's 600,000ms. Other descriptions retain the editor's wording (occasionally split between summary and expanded explanation).

Not placed as new form controls: existing user-file values **not rendered by this editor** (`historian.module_model`, `historian.module_fallback_models`, `historian.temperature`, `embedding.max_input_tokens`, `shadow_embedding`, `subc.connection_file`) and raw-editor-only `system_prompt_injection.skip_signatures`. These would remain available in the existing Raw JSONC editor in a real implementation; a raw editor is intentionally not simulated here. No new config fields are proposed.

## Open questions / implementation boundaries

1. **Retired ≠ unused.** Thirteen older-model rows are manually annotated “Review” from the supplied retired-looking list, not asserted to be retired or unused by the app. “Remove unused overrides…” opens a caution/review dialog and can preview hiding those rows with Undo. Reliable retirement needs authoritative catalog metadata; “unused” needs model-usage data and a defined time window. Neither is provided by this mockup. A production action should require individual review, not automatic deletion on this heuristic.
2. **Lifecycle audit.** Do embedding changes, Dreamer registration, or subagent extension changes also require a restart in every harness? Only confirmed lifecycle requirements are badged here; absence of a badge is not a new runtime guarantee. Audit before implementation.
3. **Default drift.** Editor and schema differ on auto-search score (0.55 vs 0.6), historian slider fallback (300,000 vs 600,000ms), task default schedules, and SQLite bounds. This proposal uses actual configured schedules and SQLite values, preserves the editor's SQLite descriptions, and takes missing score/timeout defaults from the schema. Resolve the broader drift in implementation, not in this design-only change.
4. **Scope / persistence.** This is user-config only. A production redesign must preserve project trust restrictions, unknown JSONC fields/comments, save guards, and harness-specific qualifier semantics. Browser input changes here have no validation or save pipeline; arbitrary custom cron is shown as “Custom cron · edit” rather than guessing its meaning. Timezone follows the existing scheduler; no timezone config is invented.
5. **Discoverability.** Does Ufuk prefer the overrides disclosure collapsed (this proposal, to keep defaults and reclaim switches in the first screen), or open by default? Should large task tables keep descriptions inline, as here, or move them to an accessible detail disclosure?
