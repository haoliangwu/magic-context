## 2. Check (pi-plugin): the lock fixture raced its own preceding pass

**First broken fixture commit:** `083f1f8045` added the replay/refusal cases to
the original first-turn fixture from `9a412178a6`. First master integration:
`cf032df95e`. The first observed red master job in the checked sequence is
[`f1661af0ca`, job 110952482624](https://github.com/cortexkit/magic-context/actions/runs/37041506307/job/110952482624);
the preceding integration's Pi job passed, consistent with an intermittent race.

**Evidence before choosing the fix:** [latest job 111449421453](https://github.com/cortexkit/magic-context/actions/runs/37206755794/job/111449421453)
fails at the fixture's `writer exit 1`, not a turn-budget assertion. The fixture
discarded writer stderr and waited for any stdout chunk, without rejecting that
readiness wait on exit. The preceding context pass schedules deferred indexing
and persistence writes; its one `setImmediate` is not a drain barrier.

Instrumentation and ordinary local/isolated Linux runs did not spontaneously
reproduce the CI exit. A controlled Linux x64 reproduction ran the **original
writer program** against a competing transaction and captured:

```text
code: 1, stdout: ""
SQLiteError: database is locked
errno: 5, code: "SQLITE_BUSY"
at ... db.exec("BEGIN IMMEDIATE")
Bun v1.4.2 (Linux x64)
```

The holder has no busy handler, so a transient preceding-pass write can kill it
before `locked` is printed. CI cannot supply the discarded stderr retroactively;
the controlled reproduction confirms this failure mechanism, rather than claiming
to have captured the exact CI child's error. Its one-second release also made
replay cases vulnerable to measuring an already-unlocked turn on a loaded runner.

**Fix:** use an independent SQLite worker with a synchronous shared-memory
rendezvous. The parent's deferred writes cannot run during lock acquisition.
Readiness means `BEGIN IMMEDIATE` succeeded; setup errors include their detail.
Replay/refusal holders release only after assertions, and every turn asserts
that the lock is still held. The first-turn case retains its 3200 ms automatic
release. The 1500 ms turn bound, production 5000 ms connection timeout, 250 ms
product acquisition policy and all original replay/refusal assertions remain.
Two fixture regressions prove the actual SQLite lock and setup-error reporting.

**Proof:** all ten holder/turn tests pass on macOS and Linux x64. The entire exact
Pi CI job (typecheck, lint, build, parallel suite) passes with fresh Linux deps:
**1495 pass, 0 fail**, 138 files. Existing three skipped tests were not changed.
No product busy-policy change was necessary.

## 5. OMP idle replay: lsof was timing out on name resolution

**First observed failing master commit:** `0d505632da`,
[run 37217334445, job 111481274918](https://github.com/cortexkit/magic-context/actions/runs/37217334445/job/111481274918).
The probe was introduced by `61136f0ea1` and integrated by `9304b7abf5`;
OMP host lanes from that integration until this run were prerequisite-skipped.
Earlier OMP green lanes predate this probe, so they are not evidence that the
new probe passed. CI history was checked with `gh run list --workflow ci.yml
--branch master` and each lane's job conclusions, including the older OC2 lane
name rather than treating skipped jobs as green.

**Evidence:** the requested CI log contains **status 124**, not lsof status 1
or a missing-command status. Both calls exhaust the existing ten-second
`timeout`, with empty stdout/stderr (target PIDs **2919 / 2963**). The preceding
usage-less OMP test successfully inventories its host. A missing lsof binary,
partial listing or already-exited PID does not explain that timeout pattern.

The harness already exposes the direct `bun <OMP cli.js> --mode rpc` child's
PID, not a shell/package-runner wrapper, and refreshes it after restart. On a
real Linux OMP host, tracing the original `lsof -p <pid> -Fn` showed repeated
reverse-DNS requests to UDP **53** for socket names; it took **1117 ms** versus
**67 ms** for `-nP`. The existing Pi home-isolation probe already uses `-n -P`.
OC2 samples its entire process group and requires the private database inode;
its successful inventories are not a reason to accept an empty OMP inventory.

For a controlled Linux reproduction, after warming the actual OMP host, point
only the disposable container's resolver at a non-answering local UDP socket.
The **original** command reproduces CI's exact result:

```text
OLD_DNS_BLACKHOLE {"status":124,"elapsedMs":10004,"stdout":"","stderr":""}
NEW_DNS_BLACKHOLE {"elapsedMs":9,"pid":637,"databases":[".../context.db-wal",".../context.db-shm",".../context.db"]}
DNS_CONTROL: 2 checks passed
```

The runner did not retain a DNS trace, so this is a demonstrated failure
mechanism, not a claim to have recovered its particular DNS outage. No timeout
increase or retry is needed: numeric socket names do not change filesystem
paths or omit any descriptors.

**Fix:** use `lsof -nP -p <pid> -Fin`, retaining the ten-second bound and strict
nonzero-exit failure. Verify PID existence and require the exact private
`context.db` path **and inode** for OMP, not merely any `.db` opened by that PID.
This rejects stale/wrapper PIDs while keeping every forbidden-path check.
Other host and Rust module inventories use the same numeric sampling with
their existing database-presence checks; OC2 retains its process-group guard.

**Containment controls:** three real descriptor fixtures prove the private
inode, reject an out-of-fixture sentinel, and reject a wrapper-like PID holding
only an unrelated private database. Neutralizing the path policy, after staging
the live implementation, makes only `host inventory rejects a real forbidden
open database outside the fixture` fail; the other two controls remain green.
Diff-stat is **1 file, 2 insertions, 1 deletion** during the mutation and empty
after index restore plus touch.

A second control preloads a held, throwaway `forbidden-omp.db` descriptor into
the **actual OMP host**, outside its fixture but still under the task temp root.
Only `idle TTL head replay [omp] > folds the expired head once without a host
restart` fails, naming that path through `assertContained`; all three descriptor
controls stay green. Diff-stat is **1 file, 2 insertions** during the invocation
mutation and empty after index restore plus touch. The preload and mutants are
not committed. The full restored OMP file and descriptor controls pass again:
**6 pass, 0 fail**. The 41 pre-existing host/opt-in skips are unchanged.
