# v0.49.21

This patch makes Pi and Oh My Pi sessions more reliable and releases idle local embedding memory. It also adds optional hosted search reranking and improves documentation-maintenance fallbacks.

## Upgrading

- Restart OpenCode, Pi, or Oh My Pi after updating. No database migration is needed.

## New

- Optionally configure hosted `ctx_search` reranking with a user-level [`rerank` block](https://github.com/cortexkit/magic-context/blob/master/CONFIGURATION.md); local reranking remains the default (#765, thanks @XWIlluDelu).

## Fixed

- Oh My Pi sessions continue after tag-prefix cleanup, including saved history and forks (#766, thanks @sisttri and @Qiiks).
- Local embedding processes stop after ten idle minutes and restart on demand. OpenCode 2 releases embeddings when their last context closes (#767, thanks @LouisLau-art).
- Documentation maintenance tries the configured fallback model for invalid proposal JSON and recognizes formatted empty proposals as no changes (#768, thanks @breakbeatkid).
- Older Pi and Oh My Pi sessions no longer refuse turns after their first local tag update (#769, thanks @sisttri).
- Pi and Oh My Pi limit database lock waits to the remaining turn budget instead of leaving turns stuck (#770, thanks @andrewsoonqn).
- `map-memories` no longer promises a fallback attempt when the remaining budget cannot allow it (#771, thanks @breakbeatkid).
- Pi sessions no longer refuse turns immediately after another session's slow tag loading fails.
- OpenCode 2 message search keeps up with long sessions, catches up on previously missed messages, and reflects reverted history (#772, thanks @null-axiom).
- Oh My Pi no longer refuses turns after switching models when an earlier reply was interrupted during thinking (#686, thanks @Qiiks for the report and @Zireael for the test case).
- Replies containing only a copied tag no longer send an empty part that strict OpenAI-compatible providers reject, and affected sessions recover automatically (#775, thanks @yongwun).
- Updated Zod to 4.6.7 to address a memory-exhaustion vulnerability in collection validation.
