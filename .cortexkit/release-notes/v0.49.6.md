# v0.49.6

This patch release stops turns from being interrupted when Magic Context's database is briefly busy. There is no database migration.

## Upgrading

- **No migration.** `context.db` stays at schema 95 and `store.db` at schema 63. Restart OpenCode 1, OpenCode 2, Pi or Oh My Pi after updating.

## Fixed

- **Turns are no longer interrupted when the database is briefly busy.** Magic Context saves each turn's state before the request is sent. When another process (another OpenCode or Pi window, the dashboard, or a background task) was writing at the same moment, a turn waited only 250 ms for the database. If it couldn't safely reuse the last request it sent, it stopped the turn, and the session showed "Interrupted" with no reason. A turn now waits up to 2 seconds before giving up. Magic Context still never sends a session's history unmanaged: if the database stays busy longer, it reuses the last request it sent when that is safe, and otherwise stops the turn as before. [`60206b50ed`](https://github.com/cortexkit/magic-context/commit/60206b50ed).
