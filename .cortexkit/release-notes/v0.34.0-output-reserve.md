# Output-token reservation in context budgets

Magic Context now measures pressure against a model's **safe input window**. Shared-window providers reserve their advertised output allowance from the combined context window (with a 25% cap), while already pre-carved input limits are left unchanged. Google/Gemini's proven separate output quota keeps the full input window. A user-only `output_reserve` setting can override the reservation globally or per model; `0` disables it.

This intentionally changes displayed percentages and absolute compaction points: `/ctx-status`, sidebars, and the Pi TUI now divide usage by the safe window rather than the larger raw catalog context. Shared-window sessions compact earlier so `prompt + max_tokens` cannot cross the provider wall.

Because output headroom is now explicit, the maximum `execute_threshold_percentage` and token-threshold clamp rise from 80% to 90%. The remaining ~10% of the safe input window is reserved for mid-turn growth. Force materialization, emergency drain catch-up, and tiered emergency drop derive from the effective execute threshold (`max(85, threshold + 2)`), while the provider-wall emergency block remains fixed at 95%.

## Migrating hand-carved context limits

If a configured `context` limit already subtracts output headroom and provider slack from the model's true combined window, restore the true combined value or set `output_reserve: 0`. Otherwise Magic Context reserves output headroom a second time. For example, a hand-carved `context: 110000` with a 16,000-token output allowance now produces a 94,000-token safe input budget; use the model's true combined limit instead when 110,000 was already intended to be the safe input ceiling.
